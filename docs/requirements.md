# Requirements

> Generated by scan-analyst on 2026-04-28. Sources: test files, implementation files, README, CLAUDE.md, prd_digest.md.

---

## Goals

- Provide real-time speech-to-text captioning for conference scenarios with sub-2-second end-to-end latency. `[CONFIRMED]` (README, CLAUDE.md performance target)
- Support bidirectional Korean ↔ English translation using LLM-quality contextual translation with fallback. `[CONFIRMED]` (tests/test_app.py: TestTranslateWithLlm, TestDetectLanguage)
- Enforce per-user usage-based quotas with admin override capability. `[CONFIRMED]` (tests/test_auth_module.py: TestCheckUsageLimit)
- Keep long-term AWS/OpenAI credentials server-side; expose only short-lived ephemeral tokens to the browser. `[INFERRED]` (services.py:31-84, components/webrtc.html:1516-1522)
- Support Docker-based deployment compatible with ALB/reverse-proxy environments. `[CONFIRMED]` (Dockerfile, docker-compose.yml)

---

## Primary Users

- **Operator (Staff)**: Controls the caption pipeline (start/stop), selects audio device, shares screen with audience. `[INFERRED]` (app.py sidebar controls, webrtc.html settings panel)
- **Audience**: Reads captions displayed on a large or shared screen; does not interact with controls. `[INFERRED]` (fullscreen mode, credit-roll UI in webrtc.html)
- **Administrator**: Creates and manages user accounts, sets usage quotas, monitors usage statistics, exports logs. `[CONFIRMED]` (admin.py, tests/test_database.py: TestUser, TestUsageLog)

## Out of Scope

- Multi-language support beyond Korean ↔ English (translation module only detects Korean vs. non-Korean)
- SRT/VTT caption file export or audio recording
- Terminology glossary or custom dictionary management
- Multi-room or multi-session concurrent operation
- Automatic WebRTC reconnection on failure (manual restart required in MVP)
- CI/CD pipeline (no GitHub Actions workflows present in repository)
- Static type checking (no mypy or pyright configuration)
- Test coverage enforcement thresholds (pytest-cov installed but no minimum coverage configured)
- Display of per-user remaining time in the sidebar (commented out in auth.py:241-266)

### Stage Composite View — explicitly excluded (appended 2026-08-23)

- PDF/PPT upload and slide page synchronisation. The presentation source is screen/window capture (`getDisplayMedia()`) only. There is no deck parsing, no page-turn detection, and no slide-index event.
- Remote control of the presentation deck from the stage page (the stage page is display-only; the presenter's own remote drives the deck).
- Global (non-per-room) branding defaults, branding templates, or inheritance between rooms. Stage branding is configured per room in `rooms.stage_config`.
- Capture recording, capture audio, and picture-in-picture / multiple simultaneous capture sources.
- Image processing of uploaded logos (resize, thumbnail generation, CDN upload). Assets are served as uploaded.
- A language switcher inside the stage page. The caption language is fixed by the `?lang=` query parameter to avoid adding focusable controls that could intercept presenter remote keys (NFR-025).

### Live Presentation Control — explicitly excluded (appended 2026-08-30)

- **Any control surface on the stage page.** FR-084/FR-085 change the stage screen's language and caption size at runtime, but the trigger is always an SSE `control` frame applied programmatically. The exclusion above stands unchanged: no switcher, no slider, no button, no focusable element on `/stage/{room_id}` (NFR-030).
- **Persisting the caption font scale in `rooms.stage_config`.** The blob is the administrator's pre-event branding record and the admin form saves it through a `normalize → save` round trip that silently drops keys it does not render — a venue-time value stored there would be reset without a log line the next time an administrator edited branding. The scale is live process state, replayed to reconnecting clients via the connect snapshot. A server restart resets it to 1.0; the operator's recovery is one slider move.
- **Forcing a language change onto an attendee who chose their own.** A `control` frame changes the room's *default* channel only.
- **Adding presentation state to the Streamlit component bootstrap payload.** Any BOOT field that can change mid-session remounts the component iframe and tears down the running pipeline (RL-028). Live controls travel over the already-open WebSocket instead.
- **Per-viewer or per-device caption scale.** The scale is a single room-wide value.

## Assumptions

- The OpenAI model used for SDP negotiation in the browser (`gpt-4o-realtime-preview-2024-10-01` in webrtc.html:1801) differs from the model requested in the server-side session creation (`gpt-4o-realtime-preview-2024-12-17` in services.py:49). This discrepancy may indicate one is outdated. Intent is not fully clear.
- The AWS legacy connection path (`initializeAWSConnection`, `connectAWSTranscribe` in webrtc.html:1837-2163) is present but labeled "레거시 - 사용 안함" (legacy - not in use). It remains as dead code. Current production path is OpenAI WebRTC only.
- `usage_limit_seconds=0` for admin accounts is treated as unlimited by the current check (`get_remaining_seconds` would return 0 - 0 = 0, but admins bypass the check via role check first). This means the check order in `check_usage_limit` is critical to correctness.
- README references "PBKDF2-SHA256 with Salt" in the tech stack but the actual implementation uses bcrypt throughout (`database.py`). The README is inaccurate; tests confirm bcrypt.
- `pandas` is used in admin.py for dataframe display and CSV export but is not listed in `pyproject.toml` dependencies. This may cause an import error in fresh environments.
- The `speechrecognition` package is listed in dependencies but no import of it appears in any application code. It may be an unused dependency.
- Audio sample rate is set to 16000 Hz in both browser constraints and AudioContext. This is a line-input optimization assumption; behavior with microphones at other native sample rates has no test coverage.
