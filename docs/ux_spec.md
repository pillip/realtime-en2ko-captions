## Information Architecture

### Navigation Structure

The application uses Streamlit's multi-page routing with authentication gating at each entry point. There is no shared navigation bar; routing is handled by Streamlit's internal page mechanism and URL paths.

```
/ (Main Caption Viewer)
  [Auth gate: requires login]
  Sidebar: User info, system controls, connection status
  Main area: Embedded caption viewer (webrtc.html iframe)
    Overlay: Settings FAB (top-right)
    Overlay: Fullscreen FAB (top-right, below settings)
    Overlay: Status chips (bottom-left)
    Overlay: "Back to live" button (bottom-right, conditional)
    Drawer: Settings panel (slides from right)

/admin (Admin Dashboard)
  [Auth gate: requires admin role]
  Sidebar: User info with logout
  Main area: Tabbed dashboard
    Tab 0: User Management (user table + edit/delete forms)
    Tab 1: Create User (registration form)
    Tab 2: Usage Statistics (filtered metrics + charts)
    Tab 3: Usage Logs (paginated table + CSV export)

/login (Standalone Login Page)
  Centered layout, no sidebar
  Login form + admin login button
  Service feature cards below
```

## Key Flows

### Flow: User Login (Inline on Main Page)

- **Trigger**: Unauthenticated user navigates to `/`
- **Steps**:
  1. `init_session_state()` checks for existing authentication in `st.session_state`
  2. If not authenticated, attempts cookie-based session restore (`restore_session_from_cookie`)
  3. If restore fails, `display_login_form()` renders a Streamlit form with username and password text inputs and a "로그인" submit button
  4. User enters credentials and clicks "로그인"
  5. If fields are empty, inline error: "사용자명과 비밀번호를 입력해주세요."
  6. If fields are filled, form is hidden via CSS, "로그인 처리 중..." info message displays for 0.5 seconds
  7. `login_user()` authenticates against bcrypt-hashed password in SQLite
  8. On success: session state set, 24-hour cookie created, page reruns to show main caption viewer
  9. On failure: error message "사용자명 또는 비밀번호가 잘못되었습니다." displayed for 1 second, then form re-shown
- **Success**: User sees main caption viewer with sidebar controls
- **Error paths**:
  - Empty fields: inline error, form remains visible `[INFERRED]` auth.py:334-335
  - Wrong credentials: error toast, form re-shown after 1 second delay `[INFERRED]` auth.py:317-322
  - Inactive account: `authenticate()` returns None (same UX as wrong password) `[CONFIRMED]` tests/test_database.py:TestUser.test_authenticate_inactive_user
- **Edge cases**:
  - Cookie from expired or deleted user: restore fails silently, login form shown `[INFERRED]` auth.py:84-97
  - Multiple tabs: each Streamlit session has independent session_state; cookie provides cross-tab persistence `[INFERRED]`

### Flow: Start Caption Pipeline

- **Trigger**: Authenticated operator clicks "🎯 시작" button in sidebar
- **Steps**:
  1. "시작" button is enabled only when `action` state is "idle", "stop", or "error"
  2. Click triggers spinner overlay: "시작 중..."
  3. Server calls `create_openai_session()` to get ephemeral token from OpenAI
  4. Session data stored in `st.session_state["openai_session"]`
  5. State transitions to "start"; page reruns
  6. Sidebar shows "🟢 서비스 실행 중" success badge + hint: "자막 세부 설정은 화면 우상단 ⚙️ 버튼을 클릭하세요"
  7. Caption viewer receives bootstrap JSON with `action: "start"` and `openai_session` data
  8. Browser auto-executes: `ensurePermission()` -> microphone permission prompt
  9. If permission granted: `listMics()` populates device dropdown, `connectOpenAIRealtime()` starts WebRTC
  10. Status chip transitions: "대기중" -> "권한 요청 중" -> "연결 중" -> "🎤 음성 인식 중"
  11. Welcome state (🎙️ icon + instructions) remains until first caption arrives
- **Success**: Status chip shows "🎤 음성 인식 중" (green); captions begin appearing
- **Error paths**:
  - OpenAI session creation fails (ValueError): sidebar shows "❌ {error message}", state becomes "error" `[INFERRED]` app.py:182-185
  - Microphone permission denied: status chip shows "권한 필요" (red), toast "마이크 권한이 필요합니다" `[INFERRED]` webrtc.html:1448-1451
  - WebRTC connection fails: status "연결 실패" (red), toast with error message, connection cleaned up `[INFERRED]` webrtc.html:1827-1833
  - AWS credentials missing: sidebar shows error + info text about .env, `st.stop()` prevents further rendering `[INFERRED]` app.py:78-81
- **Edge cases**:
  - Token expiry mid-session: no auto-refresh; manual restart required `[CONFIRMED]` CLAUDE.md, docs/requirements.md Risks table
  - WebSocket server not yet started: port may be None in bootstrap JSON `[INFERRED]` app.py:126-127

### Flow: Stop Caption Pipeline

- **Trigger**: Operator clicks "⏹️ 정지" button in sidebar
- **Steps**:
  1. "정지" button is enabled only when `action` state is "start" or "starting"
  2. Click sets state to "stop", clears `openai_session` from session_state

- **Success**: Viewer shows welcome state, status "대기중", all connections closed
- **Error paths**:
  - Connection close error: caught silently, logged to console `[INFERRED]` webrtc.html:2436-2438
- **Edge cases**:

### Flow: Real-time Captioning (During Active Session)

- **Trigger**: Audio input detected after pipeline is started
- **Steps**:
  1. AudioWorklet captures PCM16 audio at 16kHz, 1024-sample buffer (~64ms chunks)
  2. WebRTC DataChannel sends audio to OpenAI Realtime API
  3. OpenAI detects speech start: status chip changes to "음성 감지됨" (blue pulsing)
  4. OpenAI detects speech stop: status changes to "음성 처리 중" (blue pulsing)
  5. Transcription completed event arrives: original text appended as `.original` caption line (gray italic, white left border)
  6. Transcript forwarded to Python WebSocket server for translation
  7. Translation typing line created: empty `.typing` element (yellow border, cursor animation)
  8. Translation result received: typing line transitions to `.stable` (white text, green left border)
  9. Auto-scroll fires if user is at bottom of viewer
  10. Welcome state is removed on first caption
- **Success**: Paired original + translation lines appear in credit-roll style
- **Error paths**:
  - Translation error: typing line removed, toast "번역 오류: {message}" `[INFERRED]` webrtc.html:1762-1767
  - Usage exceeded: toast with message, WebSocket closed, connection terminated `[INFERRED]` webrtc.html:1750-1758
  - OpenAI error: status "오류" (red), toast "OpenAI 오류: {message}" `[INFERRED]` webrtc.html:1700-1703
- **Edge cases**:
  - Caption DOM capped at 100 lines; oldest removed when exceeded `[INFERRED]` webrtc.html:1304-1307
  - Duplicate/incomplete transcripts filtered by `shouldRequestTranslation()` and `isTranscriptComplete()` `[INFERRED]` webrtc.html:2167-2228
  - Translation timeout: if no response in 2500ms, typing line removed `[INFERRED]` webrtc.html:2295-2307

### Flow: Scroll Control (Back to Live)

- **Trigger**: User scrolls up in the caption viewer while captions are flowing
- **Steps**:
  1. Scroll event detected; if 800ms+ since last auto-scroll, marked as user scroll
  2. `isUserScrolling` set to true; auto-scroll disabled
  3. After 250ms debounce, `updateScrollState()` checks if user is near bottom (within 50px)
  4. If not at bottom and user is scrolling: "📺 실시간으로 ⬇️" button appears (green pill, bottom-right, gentle bounce animation)
  5. User clicks button: `isUserScrolling` reset to false, `autoScrollToBottom()` called
  6. Auto-scroll uses smooth behavior with double `requestAnimationFrame` for DOM stability
  7. Button hides when scroll reaches bottom
- **Success**: User returns to live scroll position; button disappears
- **Error paths**: None significant
- **Edge cases**:
  - Button suppressed for 1 second after auto-scroll to prevent false appearance `[INFERRED]` webrtc.html:1329-1331

### Flow: Stage Screen Setup

> Appended 2026-08-23. `[PLANNED]` — not yet implemented. Delivered by ISSUE-37 to ISSUE-42.

- **Trigger**: Event staff need the presentation deck and the translated captions on one stage-front screen.
- **Preconditions**: A room exists (ISSUE-26 lifecycle) and an operator is assigned; `VIEWER_BASE_URL` points at a host the stage PC can reach.
- **Steps**:
  1. **(Admin, before the event)** Open the admin dashboard → 룸 관리 탭 → "🎬 무대 화면 설정", select the room.
  2. Enter 행사 타이틀 and 행사 부제, choose the caption column ratio (`1/4` or `1/3`), upload 주최 / 주관 / 후원 logos per group, and save. Values persist to `rooms.stage_config`; logo files land in `data/branding/{room_id}/`.
  3. Copy the stage URL (`{VIEWER_BASE_URL}/stage/{room_id}`) or download its QR from the same section, and hand it to the stage PC operator.
  4. **(Stage PC, at the venue)** Open the stage URL in Chrome/Edge and put the browser into fullscreen on the projector output (F11 — the page never does this for you, by design).
  5. The page renders the header bar, the title card in the presentation area, the logo bar, and the caption column. The caption column immediately connects to `/stream/{room_id}` and shows the waiting state.
  6. Click "발표자료 연결". The browser's screen-picker dialog opens (one user gesture is mandatory).
  7. Select the presentation window (or the display the deck runs on). Capture starts at `frameRate.ideal = 30`, the video replaces the title card and is letterboxed to 16:9. A Screen Wake Lock is requested so the display does not sleep.
  8. Click back into the presentation app. The stage page releases focus and does not take it back; the presenter remote's arrow / PageUp / PageDown / Space keys go to the deck, not to the browser.
  9. **(Operator, separately)** Start the caption pipeline from the operator screen as usual. Translated captions begin flowing into the stage page's right column with typewriter smoothing.
- **Success**: One screen shows event title, deck at correct aspect ratio, sponsor logos, and live captions; the presenter drives the deck normally with their remote; playback stays smooth for the full session.
- **Error paths**:
  - Screen-picker cancelled / `NotAllowedError`: title card stays, generic guidance shown, the "발표자료 연결" button remains available. No internal error text (RL-006).
  - Stage page itself selected as the source (infinite mirror): warning banner + reselect action; capture is not force-stopped.
  - Presenter clicks the browser's "공유 중지", or the source window closes → track `ended`: presentation area reverts to the title card with "발표자료 다시 연결"; captions keep flowing uninterrupted.
  - SSE disconnect: reconnect pill at the bottom of the caption column; EventSource retries on its own.
  - Unknown or mistyped `room_id`: friendly 404 page, same as the viewer route.
  - Logo file missing on disk (deleted after configuration): that single `<img>` hides itself via `onerror`; the bar and the rest of the layout stay intact.
  - Screen Wake Lock unsupported or denied: silently skipped, everything else works (RL-008).
- **Edge cases**:
  - Very wide displays (e.g. 3440×1440): the 16:9 presentation box shrinks to fit height and the header/logo bars absorb the leftover vertical space — the deck is never cropped or stretched.
  - Empty event title: the header bar shows the room name instead and keeps its height, so the left column geometry does not shift.
  - All logo groups empty: the logo bar collapses to zero height and the presentation area grows into it.
  - Long single tokens (URLs, product names) in a caption: wrapped rather than producing a horizontal scrollbar in the narrow column.
  - Stage window unfocused but still visible on the projector: capture frames continue; the caption typewriter runs on `requestAnimationFrame`. If the page becomes genuinely hidden, the in-flight line snaps to its final text instead of queueing a backlog.
  - Session runs past 30 minutes: caption DOM stays capped at 60 nodes with at most one animation loop, so nothing accumulates (NFR-025).

### Flow: Operator Stage Mode Selection and Launch

> Appended 2026-08-30. `[PLANNED]` — not yet implemented. Delivered by ISSUE-47. Extends "Flow: Stage Screen Setup" above by removing its step 9 split: the operator no longer has to run the ordinary caption page and `/stage/{room_id}` as two separate sessions.

### Flow: Operator Live Presentation Control (Language and Caption Size)

> Appended 2026-08-30. `[PLANNED]` — not yet implemented. Delivered by ISSUE-52, ISSUE-53, ISSUE-54.
> Fixes a measured production defect: the operator ran `ko → vi`, the translation was genuinely
> Vietnamese in `usage_logs`, and the stage screen showed Korean — because publish resolved the
> channel from the live session setting while page render resolved it from a `rooms` row nobody
> ever updated.

- **Trigger**: Mid-event, the operator needs to change the caption language for the room, or the captions are too small / too large for the venue.
- **Preconditions**: Operator is authenticated with an assigned room. The stage screen (and/or the audience viewer) is already open on `/stage/{room_id}` or `/view/{room_id}`.
- **Steps**:
  1. The operator opens the settings panel (⚙ FAB, top right of the caption component on `:8501`).
  2. **Language** — the operator changes 출력 언어. The panel states that this sets the default caption language for the stage and viewer screens, and that attendees who picked their own language keep it. No confirmation dialog; there is no "apply" button.
  3. The change travels over the already-open WebSocket (`language_update`). The server records it on the room row and broadcasts a `control` frame to every language channel of the room.
  4. Already-open stage/viewer pages that have **not** been pinned to a language re-subscribe: their caption column clears, the waiting message reappears in the new language, and captions resume in that language. The presentation area, branding and screen capture on the stage page are untouched.
  5. **Caption size** — the operator drags 무대 자막 크기 (0.8× – 1.6×, default 1.0×). The value is shown next to the slider as `1.0×`, `1.4×` and so on.
  6. Stage and viewer captions grow or shrink immediately. The presentation area and the capture playback do not change.
- **Success**: The stage screen shows the right language at the right size without anyone touching the stage PC and without the caption pipeline, the microphone, or the screen capture being interrupted.
- **Error paths**:
  - **Session not started yet** (WebSocket not open): the language/size change is kept locally and the panel does not claim it has been applied. It takes effect the moment the operator presses 시작 — authentication records the language and emits the control frame.
  - **Unsupported language code** (stale value in `localStorage`, hand-edited request): the server rejects it, the room row is untouched, no control frame goes out, and the operator sees a generic message with no internal error text (RL-006).
  - **Font scale out of range**: rejected server-side and clamped client-side; the layout never breaks.
  - **SSE disconnect during the change**: EventSource reconnects on its own and receives the current state as a snapshot frame immediately after connecting, so it lands on the correct language and size rather than the one it had before the drop.
- **Edge cases**:
  - **An attendee who chose their own language is never pulled off it.** A `/view/` attendee who selected 베트남어 from the dropdown, or anyone who opened `/stage/{room_id}?lang=ko` explicitly, keeps that language and receives only the font-scale part of the control frame. This is the difference between "the room's default changed" and "your screen changed", and the operator's copy says so — otherwise the operator reports "I changed the language but the back row still sees the old one" as a bug.
  - **Redundant control frames are no-ops.** Reconnect snapshots and repeated announcements naming the language already in use do not close and reopen the stream, so captions do not blink.
  - **The sentence in flight finishes in the old language.** Translation is per-utterance; the switch applies from the next transcript. This is stated in the copy rather than engineered around.
  - **Stage page reloaded mid-event** (or opened late): it receives the current language and scale as its first frame, so it does not start at the room's stored defaults and then jump.
  - **Server process restarted**: the font scale returns to 1.0 because control state is process memory, not persisted. The language survives, because ISSUE-52 wrote it to the room row. Recovery for the scale is one slider move.
  - **Two operators on the same room**: the last change wins, and both operators' sliders converge on the server value at their next authentication. There is no per-operator scale.
- **Non-goals inside this flow**: no control appears on the stage screen itself, and no new field enters the Streamlit component bootstrap payload — the first would give the stage window a way to steal presenter focus (NFR-025/NFR-030), the second would remount the component iframe and tear down the running pipeline (RL-028).

  - **Empty (자막 미시작)**: Caption column shows "잠시 후 시작됩니다" in the selected language; the left column is unaffected and can already be showing capture.
  - **Active**: Capture video letterboxed in the presentation area, captions flowing in the right column.
  - **Error — 캡처 거부 (`NotAllowedError`)**: Title card stays, generic guidance text appears. No internal exception text is shown (RL-006).
  - **Error — 자기 캡처(무한 거울)**: Warning banner "무대 화면이 캡처되었습니다. 발표자료 창을 선택하세요" plus the reselect action. Capture is not force-stopped.
  - **Error — 캡처 트랙 종료**: Presentation area reverts to the title card with a "발표자료 다시 연결" action. Never a black frame. Captions keep flowing throughout.
  - **Error — SSE 끊김**: "연결이 끊어졌습니다. 재연결 중…" pill at the bottom of the caption column; clears automatically when EventSource reconnects.
  - **Ended (`session_end`)**: Caption column switches to "세션이 종료되었습니다"; the presentation area and branding remain as they were.
  - **404 (알 수 없는 룸)**: Same friendly not-found page as `/view/{room_id}`.
- **Data dependencies**: `Room.get_by_id(room_id)` for name / status / `primary_output_lang`; `rooms.stage_config` (normalised server-side) injected as `{{STAGE_CONFIG_JSON}}`; `GET /stream/{room_id}?lang=` for captions; `GET /branding/{room_id}/{filename}` for logos.
- **User actions**: Start capture (one required user gesture), reselect capture source, reconnect after the track ends. Nothing else — the caption language is set via the `?lang=` query parameter, deliberately not by an on-screen control.
- **Accessibility notes**:
  - **Keyboard non-interference is the governing constraint (NFR-025)**: the page registers no document/window-level `keydown` handler and never calls `preventDefault()` on arrow / PageUp / PageDown / Space, because a presenter remote emits exactly those keys. After capture starts the page blurs the active element so focus returns to the OS/presentation app, and it never auto-calls `focus()` or `requestFullscreen()`.
  - The two buttons keep visible `:focus-visible` indicators and text labels (not icon-only) so keyboard users are not stranded (RL-010).
  - The caption stack is announced via a `aria-live="polite"` region that updates only when a line is finalised — the per-frame typewriter reveal is `aria-hidden` so screen readers are not flooded.
  - Logo `<img>` elements carry `alt` text derived from the group label; decorative repetition is avoided by leaving `alt=""` on duplicated marks.
  - Contrast follows the viewer page: current caption line pure white on `#0b0b0c`; dimmed past lines stay at or above 4.5:1 for the sizes used.
  - `height: 100vh` is always paired with `height: 100dvh` (RL-011), and full-height elements carry no vertical margin (RL-012).

### Screen: Settings Panel — Live Presentation Controls

> Appended 2026-08-30. `[PLANNED]` — delivered by ISSUE-54. Additions to the existing
> "Screen: Settings Panel (Drawer)" above; nothing already documented there changes.

- **Route**: `/` → caption component → ⚙ settings drawer (`components/webrtc.html` `#settingsPanel`). Operator only; the drawer does not exist on `/stage/` or `/view/`.
- **Purpose**: Give the operator the only two venue-time levers over what the audience actually sees — which language the room broadcasts by default, and how large the stage captions render.
- **Components added**:
  - **출력 언어** (existing `<select id="selOutputLang">`, `:645`) — unchanged control, new supporting copy underneath. The copy must carry three facts, in short separate sentences rather than one dense one: (1) this sets the default caption language for the stage and viewer screens, (2) attendees who chose their own language keep it, (3) a change made before 시작 takes effect when the session starts.
  - **무대 자막 크기** (new `<input type="range">`) — `min=0.8`, `max=1.6`, `step=0.1`, default `1.0`. Value readout beside it in multiples (`1.0×`, `1.4×`), not pixels: the stage caption size is a `clamp()` expression, so a pixel figure would be a lie at most viewport widths. Reuses the existing `.control-group` / `.slider` / value-`<span>` pattern.
- **Distinguished from the two sliders already present**: 번역 글자 크기 (`#fontSizeSlider`, 18–48 px) and 원문 글자 크기 (`#originalSizeSlider`, 12–24 px) affect **the operator's own caption view only** and are persisted to `localStorage`. The new slider affects **the audience's screens**. The labels carry that distinction — 무대 자막 크기 vs 번역 글자 크기 — because the controls sit in the same drawer and look identical.
- **States**:
  - **Session running**: both controls active; changes propagate within one SSE frame.
  - **Session not started**: both controls remain usable; the panel does not indicate that a change has reached the audience, because it has not. The change is applied at 시작.
  - **Rejected value**: generic message only, no internal exception text (RL-006). The control returns to the last accepted value.
  - **Server state present at authentication**: the slider snaps to the server's value, overriding any stale `localStorage` position. The server is authoritative; `localStorage` is a fallback for the case where the server has no state.
- **Accessibility notes**:
  - `<label for>` is programmatically associated with the range input; the value readout carries `aria-live="polite"`, matching the existing `#fsTransSize` pattern (`:738`).
  - The slider is reachable by Tab, adjustable with arrow keys, and shows a visible `:focus-visible` ring (RL-010, NFR-020).
  - **Contrast is computed against `#0e0e10`** — the settings panel's own background (`:74`) — not the `#0b0b0c` viewer canvas. Reusing an alpha that passes on one surface and assuming it passes on another is the exact shape of RL-018. The reused rules today are `.control-group label` `rgba(255,255,255,0.5)` @12 px and `.control-group span` `rgba(255,255,255,0.55)` @13 px; the numbers go into the test parametrisation, not into a judgement call.
- **Data dependencies**: WebSocket `language_update` and `stage_control` messages; `stage_control_ack` and the control snapshot on `auth_success` for the initial slider position. **No bootstrap-payload field** — adding one would remount the component iframe and destroy the running pipeline (RL-028).
